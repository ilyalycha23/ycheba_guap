4. Теоретическая часть 
4.1 Клиентские компоненты и интерактивность 
В App Router страницы и layouts по умолчанию являются Server Components. 
Официальная документация Next.js рекомендует использовать Client Components, когда 
необходимы состояние, обработчики событий, эффекты, браузерные API или 
пользовательские хуки. Граница клиентского модуля объявляется директивой "use client" 
перед импортами. (Next.js: Server and Client Components; Next.js: use client) 
"use client"; 
 
import { useState } from "react"; 
Не вся страница обязана становиться клиентской. Серверный page.tsx может 
импортировать небольшой клиентский компонент Gallery. Такой подход сохраняет 
статическую оболочку серверной и отправляет в браузер JavaScript только для 
интерактивной части. 
import PlacesGallery from "./_components/PlacesGallery"; 
 
export default function GalleryPage() { 
  return <PlacesGallery />; 
} 
4.2 Состояние и условный рендеринг 
Официальная справка React определяет useState как хук для добавления переменной 
состояния. useState возвращает текущее значение и функцию обновления, после вызова 
которой React выполняет повторный рендер. 
const [selected, setSelected] = useState<StudyPlace | null>(null); 
Когда пользователь нажимает карточку, selected получает объект. Когда окно закрывается, 
selected становится null. 
Официальный раздел React Conditional Rendering указывает, что компоненты могут 
выбирать JSX обычными средствами JavaScript: if, условным оператором и оператором 
&&. 
{selected ? ( 
  <PhotoModal place={selected} onClose={() => setSelected(null)} /> 
) : null} 
Условный рендеринг отвечает только за наличие интерфейса. Например, условие user ? 
<button> : <Link> не является серверной проверкой прав. \n3 
4.3 Обработчики событий 
Официальная документация React Responding to Events указывает, что обработчик 
передаётся JSX-элементу как функция. Для действия необходимо использовать 
семантический элемент button, а не div с onClick: кнопка имеет встроенную поддержку 
клавиатуры. 
<button type="button" onClick={() => setSelected(place)}> 
  Открыть карточку 
</button> 
Обработчики событий React распространяются вверх по дереву. Если щелчок по 
затемнённому фону закрывает модальное окно, щелчок внутри окна не должен случайно 
вызвать тот же обработчик. Для разделения действий можно проверить event.target === 
event.currentTarget или остановить распространение в контейнере диалога. 
4.4 Эффекты и очистка ресурсов 
Согласно официальной справке React useEffect, эффект используется для синхронизации 
компонента с внешней системой. В этой работе внешними системами являются события 
window, стили document, DOM-фокус и экземпляр карты. 
useEffect(() => { 
  function handleKeyDown(event: KeyboardEvent) { 
    if (event.key === "Escape") onClose(); 
  } 
 
  window.addEventListener("keydown", handleKeyDown); 
  return () => window.removeEventListener("keydown", handleKeyDown); 
}, [onClose]); 
Функция, возвращаемая из useEffect, является cleanup. Она должна отменить подписку, 
восстановить изменённое состояние документа или уничтожить экземпляр внешней 
библиотеки. 
В режиме разработки React Strict Mode может выполнить дополнительный цикл setup → 
cleanup → setup. Официальная документация объясняет, что это проверяет полноту 
очистки. Компонент не должен создавать дублирующиеся обработчики или карты. 
4.5 Ссылки на DOM через useRef 
Официальная справка React useRef определяет ref как ссылку на значение, которое не 
требуется для рендеринга. Изменение ref.current не запускает повторный рендер. 
В клиентском интерфейсе ref используется для: 
 ссылки на кнопку закрытия модального окна; 
 возврата фокуса на карточку, открывшую окно; 
 ссылки на HTML-контейнер карты; 
 хранения последнего интерактивного элемента. 
const closeButtonRef = useRef<HTMLButtonElement>(null); \n4 
После открытия диалога можно вызвать closeButtonRef.current?.focus(). После закрытия 
фокус возвращается к элементу, который открыл диалог. 
4.6 Порталы и модальные окна 
Официальная справка React createPortal указывает, что портал размещает DOM-узлы в 
другом месте документа, при этом JSX остаётся дочерним элементом того же React-
дерева. Портал удобен для модального окна, которое должно находиться поверх 
контейнеров с overflow или локальным stacking context. 
import { createPortal } from "react-dom"; 
 
return createPortal( 
  <div className={styles.overlay}>...</div>, 
  document.body, 
); 
События из портала распространяются по React-дереву, а контекст остаётся доступным. 
Поэтому модальное окно может использовать DemoAuthProvider, хотя физически его 
DOM размещён в body. 
Документация React отдельно предупреждает, что портал должен быть доступным и 
требует управления фокусом. Для требований диалога используется официальный WAI-
ARIA Authoring Practices Guide W3C. 
4.7 Доступность модального диалога 
Официальный WAI-ARIA Dialog (Modal) Pattern определяет модальный диалог как окно 
поверх основного содержимого, при котором взаимодействие с нижележащим 
содержимым недоступно. 
Контейнер модального окна должен иметь: 
role="dialog" 
aria-modal="true" 
aria-labelledby="place-modal-title" 
Основные требования клавиатурного взаимодействия из WAI-ARIA APG: 
 при открытии фокус перемещается внутрь диалога; 
 Tab и Shift + Tab не выводят фокус за границы диалога; 
 Escape закрывает диалог; 
 после закрытия фокус обычно возвращается к элементу, открывшему диалог; 
 в диалоге должна быть видимая кнопка закрытия. 
aria-modal не заменяет реальную логику фокуса. Наличие атрибута без ограничения Tab не 
делает окно полностью доступным. 
4.8 Бургер-меню \n5 
Бургер-меню состоит из кнопки и раскрывающейся панели навигации. Кнопка должна 
сообщать состояние через aria-expanded и быть связана с панелью через aria-controls. 
<button 
  type="button" 
  aria-expanded={open} 
  aria-controls="main-menu-panel" 
  onClick={() => setOpen(true)} 
> 
  Меню 
</button> 
Активный маршрут определяется usePathname. Официальная документация Next.js 
описывает usePathname как Client Component hook для чтения текущего pathname. 
Внутренние переходы выполняются через Link. 
Открытая панель использует те же принципы, что и модальный диалог: Escape, 
блокировка прокрутки, доступное имя и возврат фокуса. Полная адаптивная настройка 
размеров и контрольных точек будет продолжена в лабораторной работе № 4. 
4.9 Изображения в Next.js 
Официальная документация Next.js Image Optimization указывает, что компонент Image 
расширяет img и обеспечивает выдачу подходящего размера, визуальную стабильность и 
отложенную загрузку изображений. Локальные статические файлы можно хранить в 
public и указывать от корня URL. 
import Image from "next/image"; 
 
<Image 
  src="/images/places/library.jpg" 
  alt="Читальный зал научной библиотеки" 
  width={900} 
  height={600} 
/> 
Свойство alt описывает содержание и назначение изображения. Декоративное 
изображение может иметь alt="", но фотография предметной сущности в каталоге обычно 
требует осмысленного текста. 
width и height позволяют Next.js определить соотношение сторон и зарезервировать место. 
Если применяется fill, родительский контейнер должен задавать размеры и 
позиционирование. 
В этой работе используются локальные изображения. Для удалённых источников 
официальная документация требует явно настроить remotePatterns в next.config и задавать 
ограничения как можно точнее. 
4.10 JavaScript API Яндекс Карт 
Официальная документация Яндекс Карт определяет JavaScript API как набор JavaScript-
компонентов для публикации интерактивных карт на веб-страницах. API загружается 
внешним HTTPS-скриптом с параметрами версии, языка и ключа. \n6 
https://api-maps.yandex.ru/2.1/?apikey=КЛЮЧ&lang=ru_RU 
Документация Enabling the API указывает, что компоненты загружаются асинхронно. 
Готовность должна проверяться через ymaps.ready или параметр onload; одного события 
готовности DOM недостаточно. 
Класс Map создаёт карту внутри существующего HTML-элемента. Состояние включает 
center и zoom. 
const map = new ymaps.Map(container, { 
  center: [55.75, 37.62], 
  zoom: 12, 
}); 
Класс Placemark представляет точечный геообъект. Конструктор получает координаты, 
данные и параметры отображения. Метка появляется после добавления в глобальную 
коллекцию geoObjects карты. 
const placemark = new ymaps.Placemark([55.75, 37.62], { 
  hintContent: "Учебное место", 
}); 
 
map.geoObjects.add(placemark); 
В React контейнер карты хранится в useRef, создание выполняется в useEffect, а cleanup 
вызывает destroy. Координаты должны быть числами и соответствовать предметной 
сущности. 
4.11 Переменные окружения клиентской части 
Официальная документация Next.js Server and Client Components указывает: переменные с 
префиксом NEXT_PUBLIC_ включаются в клиентский JavaScript. Поэтому значение 
NEXT_PUBLIC_YANDEX_MAPS_API_KEY нельзя считать серверным секретом. 
NEXT_PUBLIC_YANDEX_MAPS_API_KEY=ваш_ключ 
Файл .env.local не включается в отчёт целиком и не отправляется в публичный 
репозиторий. В отчёте ключ закрывается. Для реального проекта ограничения ключа 
настраиваются в кабинете поставщика API. 
4.12 Условный интерфейс и авторизация 
В модальном окне учебный пользователь может нажать «Добавить в избранное», а гость 
видит ссылку на вход. Это демонстрирует условный рендеринг и общий контекст. 
Официальное руководство Next.js Authentication предупреждает, что ограничения 
клиентского интерфейса недостаточны для безопасности. Серверное действие, Route 
Handler и доступ к данным должны выполнять собственную проверку сессии и прав. 
В этой работе избранное хранится в Set внутри useState. Оно не является 
пользовательскими данными постоянного хранения. В лабораторных работах № 6 и № 7 
действие будет соединено с базой данных и серверной проверкой пользователя. \n7

// Создаёт доступное модальное окно с изображением, действиями и управлением фокусом. 
 
"use client"; 
 
import Image from "next/image"; 
import Link from "next/link"; 
import { useEffect, useRef, type KeyboardEvent as ReactKeyboardEvent } from "react"; 
import { createPortal } from "react-dom"; 
import { useDemoAuth } from "../../providers/DemoAuthProvider"; 
import type { StudyPlace } from "../../data/places"; 
import styles from "./PhotoModal.module.css"; 
 
// Типизируем входные свойства компонента. 
type PhotoModalProps = { 
  place: StudyPlace; 
  isFavorite: boolean; 
  onToggleFavorite: () => void; 
  onClose: () => void; 
  returnFocusTo: HTMLElement | null; 
}; 
 
// Собираем селектор элементов, которые могут получать фокус. 
const focusableSelector = [ 
  "a[href]", 
  "button:not([disabled])", 
  "input:not([disabled])", 
  "select:not([disabled])", 
  "textarea:not([disabled])", 
  '[tabindex]:not([tabindex="-1"])', 
].join(","); 
 
// Объявляем основной компонент этого файла. 
export default function PhotoModal({ 
  place, 
  isFavorite, 
  onToggleFavorite, 
  onClose, 
  returnFocusTo, 
}: PhotoModalProps) { 
  const { user } = useDemoAuth(); 
  const dialogRef = useRef<HTMLDivElement>(null); 
  const closeButtonRef = useRef<HTMLButtonElement>(null); \n20 
 
  // Синхронизируем компонент с браузерными событиями или внешним API. 
  useEffect(() => { 
    const previousOverflow = document.documentElement.style.overflow; 
    document.documentElement.style.overflow = "hidden"; 
    closeButtonRef.current?.focus(); 
 
    function handleEscape(event: globalThis.KeyboardEvent) { 
      if (event.key === "Escape") onClose(); 
    } 
 
    window.addEventListener("keydown", handleEscape); 
 
    // В cleanup освобождаем подписки и внешние ресурсы эффекта. 
    return () => { 
      window.removeEventListener("keydown", handleEscape); 
      document.documentElement.style.overflow = previousOverflow; 
      returnFocusTo?.focus(); 
    }; 
  }, [onClose, returnFocusTo]); 
 
  // Не выпускаем клавиатурный фокус за границы открытого интерфейса. 
  function keepFocusInside(event: ReactKeyboardEvent<HTMLDivElement>) { 
    if (event.key !== "Tab") return; 
 
    const focusable = Array.from( 
      dialogRef.current?.querySelectorAll<HTMLElement>(focusableSelector) ?? [], 
    ); 
 
    if (focusable.length === 0) { 
      // Отменяем стандартное действие события и выполняем собственную логику. 
      event.preventDefault(); 
      return; 
    } 
 
    const first = focusable[0]; 
    const last = focusable[focusable.length - 1]; 
 
    if (event.shiftKey && document.activeElement === first) { 
      event.preventDefault(); 
      last.focus(); 
    } else if (!event.shiftKey && document.activeElement === last) { 
      event.preventDefault(); 
      first.focus(); 
    } 
  } 
 
  // Рендерим окно в document.body поверх основного интерфейса. 
  return createPortal( 
    <div 
      className={styles.overlay} 
      onMouseDown={(event) => { 
        if (event.target === event.currentTarget) onClose(); 
      }} 
    > 
      <div 
        ref={dialogRef} 
        className={styles.dialog} 
        role="dialog" 
        aria-modal="true" 
        aria-labelledby="place-modal-title" 
        onKeyDown={keepFocusInside} 
      > 
        <button 
          ref={closeButtonRef} 
          className={styles.close} 
          type="button" 
          aria-label="Закрыть окно" 
          onClick={onClose} \n21 
        > 
          × 
        </button> 
 
        <h2 id="place-modal-title">{place.title}</h2> 
 
        <Image 
          src={place.image} 
          alt={place.imageAlt} 
          width={900} 
          height={600} 
          className={styles.image} 
          sizes="(max-width: 700px) calc(100vw - 48px), 720px" 
        /> 
 
        <p>{place.summary}</p> 
        <p> 
          <strong>Адрес:</strong> {place.address} 
        </p> 
 
        {user ? ( 
          <button type="button" onClick={onToggleFavorite}> 
            {isFavorite ? "Удалить из избранного" : "Добавить в избранное"} 
          </button> 
        ) : ( 
          <Link href="/auth/login">Войдите, чтобы использовать избранное</Link> 
        )} 
      </div> 
    </div>, 
    document.body, 
  ); 
}

    const openButton = openButtonRef.current; 
    document.documentElement.style.overflow = "hidden"; 
    closeButtonRef.current?.focus(); 
 
    function handleEscape(event: KeyboardEvent) { 
      if (event.key === "Escape") setOpen(false); 
    } 
 
    window.addEventListener("keydown", handleEscape); 
 
    // В cleanup освобождаем подписки и внешние ресурсы эффекта. 
    return () => { 
      window.removeEventListener("keydown", handleEscape); 
      document.documentElement.style.overflow = previousOverflow; 
      openButton?.focus(); 
    }; 
  }, [open]);

    setOpen(false); 
  }

    if (event.key !== "Tab") return;

      panelRef.current?.querySelectorAll<HTMLElement>(menuFocusableSelector) ?? [], 
    );

      event.preventDefault(); 
      return; 
    }

    const last = focusable[focusable.length - 1]; 
    if (event.shiftKey && document.activeElement === first) { 
      event.preventDefault(); 
      last.focus(); 
    } else if (!event.shiftKey && document.activeElement === last) { 
      event.preventDefault(); 
      first.focus(); 
    } 
  }

  return (

                      href={link.href}

                    </Link>

      ) : null}

const scriptId = "study-space-yandex-maps"; 
let mapsPromise: Promise<YandexMapsApi> | null = null; 
 
// Загружаем скрипт карты один раз и ожидаем готовности API. 
function loadMaps(apiKey: string): Promise<YandexMapsApi> { 
  if (window.ymaps) { 
    return new Promise((resolve) => { 
      window.ymaps?.ready(() => resolve(window.ymaps as YandexMapsApi)); 
    }); 
  } 
 
  if (mapsPromise) return mapsPromise; 
 
  mapsPromise = new Promise((resolve, reject) => { 
    function resolveWhenReady() { 
      if (!window.ymaps) { 
        mapsPromise = null; 
        reject(new Error("Yandex Maps API is unavailable")); 
        return; 
      } 
 
      window.ymaps.ready(() => resolve(window.ymaps as YandexMapsApi)); 
    } 
 
    const existing = document.getElementById(scriptId) as HTMLScriptElement | null; 
    if (existing) { 
      existing.addEventListener("load", resolveWhenReady, { once: true }); 
      existing.addEventListener("error", () => reject(new Error("Map script error")), { 
        once: true, 
      }); 
      return; 
    } 
 
    const script = document.createElement("script"); 
    script.id = scriptId; 
    script.src = `https://api-
maps.yandex.ru/2.1/?apikey=${encodeURIComponent(apiKey)}&lang=ru_RU`; 
    script.async = true; 
    script.addEventListener("load", resolveWhenReady, { once: true }); 
    script.addEventListener( 
      "error", 
      () => { 
        mapsPromise = null; 
        reject(new Error("Map script error")); 
      }, 
      { once: true }, 
    ); 
    // Подключаем внешний скрипт к документу. 
    document.head.appendChild(script); 
  }); 
 
  return mapsPromise; 
}
