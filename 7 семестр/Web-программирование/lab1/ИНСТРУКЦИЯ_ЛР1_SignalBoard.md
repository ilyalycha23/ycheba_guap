# Лабораторная работа № 1 — подробная инструкция

**Тема проекта:** SignalBoard — доска локальных сигналов соседям  
**Стек:** Next.js + React + TypeScript + App Router  
**Папка проекта:** `signalboard/`

Этот файл объясняет, **что сделано**, **зачем** и **как повторить / сдать** работу по методичке.

---

## 1. Концепция приложения (этап 1 методички)

| Пункт | Содержание |
|--------|------------|
| **Рабочее название** | SignalBoard |
| **Проблема** | Объявления «ищу / отдаю / предупреждаю» тонут в чатах дома и двора |
| **Целевая аудитория** | Жители одного дома, двора или ЖК |
| **Главная предметная сущность** | **Сигнал** — локальное объявление соседа (тип, текст, статус; позже — геометка и автор) |
| **Три функции (на старт)** | 1) Лента сигналов 2) Фильтры по типу 3) Личный кабинет |

Это тема **на все 7 лабораторных**. В ЛР1 — только каркас: две страницы, компонент, навигация. Сервер, БД и авторизация **пока не нужны** (появятся позже).

**Почему не TheraCity:** методичка запрещает копировать тематику ВКР. У нас сущность — сигнал соседа, а не фото/маршруты.

Структура (как в методичке):

```text
signalboard/
├── app/
│   ├── about/
│   │   └── page.tsx      ← страница /about
```

**Требования к результату (раздел 6 методички):**

1. Next.js + React + TypeScript  
2. App Router  
3. Каталог `app` в корне проекта (не `src/app`)  
4. Главная `/`  
5. Страница `/about`  
6. Хотя бы один свой React-компонент  
7. Props типизированы  
8. Компонент используется ≥ 3 раз  
9. Навигация через `next/link`  
10. `npm run lint` и `npm run build` без ошибок  
11. Нет сервера / БД / auth

## 4. Создание проекта (этап 3)

Команда (название вместо `student-project`):

```bash
npx create-next-app@latest signalboard
```

**Выбранные параметры (как в методичке):**

| Вопрос | Ответ |
|--------|--------|
| TypeScript | Yes |
| Linter | ESLint |
| React Compiler | No |
| Tailwind CSS | No |
| `src/` directory | No |
| App Router | Yes |
| Import alias | `@/*` (стандарт) |

Неинтерактивный эквивалент:

```bash
npx create-next-app@latest signalboard --typescript --eslint --no-tailwind --no-src-dir --app --no-react-compiler --import-alias "@/*" --use-npm --yes
```

Затем:

```bash
cd signalboard
npm run dev
```

Открыть: http://localhost:3000

## 6. Теория коротко (чтобы понимать код)

### React-компонент

Функция с **заглавной** буквы, возвращает JSX. Можно вкладывать компоненты друг в друга.

### JSX

Разметка внутри JS/TS. Один корневой элемент (или фрагмент). Выражения — в `{...}`.

### Props + TypeScript

Данные «сверху вниз». В ЛР1 обязателен тип props, например:

```ts
type FeatureCardProps = Readonly<{
  title: string;
  description: string;
}>;
```

### App Router

- Папка = сегмент URL  
- `app/page.tsx` → `/`  
- `app/about/page.tsx` → `/about`  
- `app/layout.tsx` — общая оболочка (`html`, `body`, `children`)  

По умолчанию страницы — **Server Components**. Директива `"use client"` в ЛР1 **не нужна**.

### `Link` из `next/link`

Клиентская навигация без полной перезагрузки страницы (в отличие от обычного `<a href>` для внутренних маршрутов).

## 7. Что сделано в файлах

### `app/ui/FeatureCard.tsx`

Карточка одной функции приложения.

- Принимает `title` и `description`  
- Props типизированы  
- На главной вызывается **три раза** (лента, фильтры, кабинет)

### `app/page.tsx` (главная `/`)

Содержит по методичке:

1. Название — SignalBoard  
2. Описание проблемы  
3. Целевую аудиторию  
4. Три функции через `FeatureCard`  
5. Ссылку `Link` на `/about`

### `app/about/page.tsx` (`/about`)

Содержит:

- название проекта  
- цель разработки  
- будущий результат  
- основную сущность (**сигнал**)  
- предполагаемые разделы (лента, карточка сигнала, создание, кабинет, auth, about)  
- `Link` обратно на `/`

### `app/layout.tsx`

Корневой layout: `lang="ru"`, metadata title/description для SignalBoard, подключение `globals.css`.

### `app/globals.css`

Базовые стили из приложения методички: сетка карточек, ссылки, focus-visible.

Файл `page.module.css` от шаблона create-next-app удалён — он не входит в требуемую структуру ЛР1.

## 10. Как объяснить «своими словами» на защите

- **Зачем Next.js:** готовая структура приложения, маршруты из папок, сборка и оптимизация поверх React.  
- **Зачем TypeScript:** ловит ошибки типов до запуска (например, передали число вместо строки в props).  
- **Зачем App Router:** URL = структура `app/.../page.tsx`.  
- **Зачем FeatureCard:** один компонент — три карточки; меняешь разметку в одном месте.  
- **Зачем Link:** правильная навигация между страницами Next.js.  
- **Почему пока нет БД:** ЛР1 — каркас концепции; данные и auth — следующие работы.
