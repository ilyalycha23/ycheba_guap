# Лабораторная работа № 5 — что сделано и почему

**Тема:** SignalBoard  
**Папка проекта:** `signalboard/`  
**Методичка:** установка PostgreSQL и подключение Prisma ORM 6.19.2

Клиентская часть ЛР1–ЛР4 сохранена. Данные по-прежнему в TypeScript-массиве. Здесь подключается база, но **предметные таблицы ещё не создаются**.

---

## Что нельзя делать в этой работе

Не запускать `prisma migrate dev`, `prisma db push` и ручной `CREATE TABLE`. Пустая база после успешного соединения — ожидаемый результат. Физическая схема появится в ЛР6.

---

## Что сделано в проекте

- `prisma` и `@prisma/client` версии **6.19.2** (фиксация курса).  
- `prisma/schema.prisma`: `generator`, `datasource postgresql`, временная модель `SetupCheck` только для генерации клиента.  
- `app/lib/prisma.ts` — один экземпляр `PrismaClient`, в development кладётся в `globalThis`. Файл серверный, без `"use client"`.  
- `scripts/check-prisma.ts` — диагностический `SELECT current_database(), current_user, inet_server_port()`.  
- `.env` хранит `DATABASE_URL`, в Git не попадает. `.env.example` содержит заполнитель.

Имена роли и базы согласованы с темой:

- роль `signal_app` (без SUPERUSER);  
- база `signalboard`, владелец `signal_app`.

---

## Что сделать на своей машине

1. Установить PostgreSQL (сервер + Command Line Tools). Пароль роли `postgres` в отчёт не писать.

2. В `psql` под `postgres`:

```sql
CREATE ROLE signal_app
  WITH LOGIN
  PASSWORD 'свой_локальный_пароль';

CREATE DATABASE signalboard
  WITH OWNER = signal_app
       ENCODING = 'UTF8';
```

3. В `.env` подставить пароль и порт:

```env
DATABASE_URL="postgresql://signal_app:ПАРОЛЬ@localhost:5432/signalboard?schema=public"
```

4. Проверки:

```bash
psql -h localhost -p 5432 -U signal_app -d signalboard
# внутри: SELECT current_database(), current_user, inet_server_port();  \dt  \q

npx prisma validate
npx prisma generate
npm run db:check
npm run lint
npm run build
```

`\dt` на этом этапе сообщает, что отношений нет. Ошибка P1000 — роль/пароль, P1001 — служба/хост/порт. Полный `DATABASE_URL` в сообщениях и отчёте не публиковать.

---

## Почему так

Приложение не должно ходить в базу как `postgres`. `DATABASE_URL` без `NEXT_PUBLIC_`, иначе секрет попадёт в клиентский бандл. Prisma не заменяет PostgreSQL: сервер хранит данные, Prisma даёт типы и запросы.
