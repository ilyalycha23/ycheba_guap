## Таблицы

| Таблица | Зачем |
|---|---|
| `User` | Зарегистрированные соседи. Пароль хранится только как `passwordHash` (bcrypt, cost 12). |
| `NeighborSignal` | Локальные сигналы для ленты, галереи и карты. |
| `TrackedSignal` | Связь многие-ко-многим: кто отслеживает какой сигнал. |

Составной первичный ключ `(userId, signalId)` не даёт добавить один сигнал дважды.  
`onDelete: Cascade` удаляет связи вместе с пользователем или сигналом. Сам сигнал при удалении пользователя не трогается.  
Индекс по `signalId` нужен для обратного поиска: внешний ключ сам индекс не создаёт.

Миграция: `prisma/migrations/20260911120000_init_signalboard/migration.sql`.  
Применённый SQL вручную не редактировать.

## Seed

`prisma/seed.ts` идемпотентный: `upsert` пользователя `neighbor@example.test`, трёх сигналов и одной связи отслеживания. Повторный запуск не увеличивает число строк.

Демо-пароль только для локальной базы: `SignalPass_2026!`. В отчёт его лучше не светить крупно, в коде seed он нужен для воспроизводимости.

```bash
npx prisma migrate dev --name init_signalboard
npx prisma db seed
npx prisma db seed
```

Если миграция уже лежит в репозитории, достаточно `npx prisma migrate deploy` или `migrate dev` без пересоздания SQL.

## Серверная авторизация

Маршруты:

- `POST /api/auth/register` → 201, конфликт email → 409;  
- `POST /api/auth/login` → одно сообщение для неверного email и пароля, 401;  
- `GET /api/auth/me` → `user` или `null`;  
- `POST /api/auth/logout` → удаляет cookie;  
- `POST` / `DELETE /api/favorites/[signalId]` — сначала `getCurrentUser`, гостю 401.  
  `userId` берётся из сессии, не из тела запроса.

Сессия: JWT (jose, HS256) в cookie `signal_session` с `httpOnly`, `sameSite=lax`, `path=/`, `maxAge` 7 дней, `secure` только в production.  
`AUTH_SECRET` генерируется локально и не публикуется. `passwordHash` в JSON не возвращается.

Клиентские формы ЛР2 пока остаются учебным прототипом: они ещё не вызывают эти API. Соединение клиента с сервером — ЛР7.

Это учебный поток, не production-auth: нет подтверждения email, восстановления пароля, отзыва токенов, CSRF, MFA и ограничения частоты запросов.

## Как проверить API

После миграции и seed:

```bash
npm run dev
```

Сценарии из методички: регистрация, повторный email, выход, неверный пароль, вход, `me`, избранное/отслеживание гостем и после входа. Cookie и JWT на скриншотах закрывать.
