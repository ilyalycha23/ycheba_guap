# Шпаргалка к защите ЛР6 — SignalBoard

Если просят «покажи» — `npm run db:status`, `\d "TrackedSignal"`, `npm run db:seed` два раза, `npm run db:studio`; затем `npm run dev` и запросы к `/api/auth/*`, `/api/favorites/{id}`.

---

## 30 секунд про работу
Три таблицы: `User`, `NeighborSignal`, `TrackedSignal` (связь многие-ко-многим, PK = `userId + signalId`, CASCADE, индекс по `signalId`).  
Миграция `init_signalboard`, идемпотентный seed через upsert.  
Авторизация на сервере: bcrypt (cost 12), JWT jose HS256 в httpOnly-cookie `signal_session`, гость получает 401.

## Частые вопросы — короткие ответы

| Вопрос | Ответ |
|--------|-------|
| PK? | Уникальная идентификация строки. |
| UNIQUE vs индекс? | Запрет дублей vs только ускорение. |
| FK? | Ссылка только на существующую строку. |
| Почему составной PK? | Пара уникальна сама, дубль невозможен. |
| Cascade? | Удалили пользователя — удалились его связи. |
| Почему индекс по signalId? | PostgreSQL не индексирует FK сам. |
| migration.sql? | Воспроизводимый SQL в Git. |
| Идемпотентный seed? | Повторный запуск — то же состояние. |
| upsert vs create? | Обновить или создать vs всегда вставить. |
| bcrypt-хеш? | Алгоритм, cost, соль, хеш. |
| Аутентификация vs авторизация? | Кто ты vs что тебе можно. |
| Stateless session? | Данные в подписанном токене, сервер не хранит. |
| Зачем подпись? | Подделка payload обнаруживается. |
| httpOnly / secure / sameSite? | Нет доступа JS / только HTTPS / защита от CSRF. |
| Зачем проверять user в базе? | Аккаунт могли удалить после выдачи токена. |
| Одно сообщение на email и пароль? | Не раскрываем, есть ли такой email. |
