# Лабораторная работа № 7 — что сделано и почему

**Тема:** SignalBoard  
**Папка проекта:** `signalboard/`  
**Методичка:** соединение клиента с сервером, Vitest и Playwright

К этому моменту есть адаптивный интерфейс (ЛР1–4), Prisma (ЛР5) и серверные маршруты (ЛР6). Клиент больше не считает источником истины массив и `DemoAuthProvider`.

---

## HTTP-контракт

| Метод и URL | Успех | Ошибки |
|---|---|---|
| `GET /api/signals` | 200 `{ signals }` | 500 |
| `GET /api/auth/me` | 200 `{ user }` | — |
| `POST /api/auth/login` | 200 `{ user }` | 400, 401, 500 |
| `POST /api/auth/register` | 201 `{ user }` | 400, 409, 500 |
| `POST /api/auth/logout` | 200 `{ ok: true }` | — |
| `POST /api/favorites/:signalId` | 201 | 401, 404 |
| `DELETE /api/favorites/:signalId` | 200 `{ deleted }` | 401 |

`NeighborSignalDTO` содержит поля карточки, координаты как `number` и вычисленный `isTracked`.  
`UserDTO` — `id`, `name`, `email`, без `passwordHash`.  
`isTracked` считает сервер по проверенному `user.id`.

Поток чтения: галерея → `GET /api/signals` → Prisma → PostgreSQL.

## Что изменилось на клиенте

- `AuthProvider` восстанавливает сессию через `/api/auth/me`. Пароль и JWT в React state не хранятся.  
- Формы входа и регистрации вызывают API, на время запроса кнопка блокируется, после успеха переход в `/gallery`.  
- Галерея загружает сигналы в `useEffect` с `AbortController`. Состояния: loading, success, empty, error + «Повторить».  
- Отслеживание пессимистичное: ждём ответ сервера, затем меняем только нужную карточку. После reload состояние остаётся, потому что оно в таблице `TrackedSignal`.  
- Модалка, карта, меню и адаптив ЛР3–ЛР4 сохранены.

Статический `app/data/signals.ts` оставлен для ленты `/signals` и сравнения полей, как требует методичка до полной замены каталога. Галерея его больше не импортирует.

## Тесты

- **Vitest** (`npm run test:unit`) — чистые функции `normalizeEmail` и `validateRegistration`, без базы.  
- **Playwright** (`npm run test:e2e`) — регистрация уникального email, отслеживание сигнала «Ищу ключи от подъезда», reload, выход, удаление тестового пользователя в `afterAll`. Один worker, `webServer: npm run start`, сначала нужен `npm run build`.

```bash
npx prisma validate
npx prisma migrate status
npx prisma generate
npm run lint
npm run test:unit
npm run build
npx playwright install chromium
npm run test:e2e
```

E2E без запущенного PostgreSQL и применённой миграции не пройдёт — это нормально: сценарий идёт через реальный сервер и базу.

## Почему проверки на клиенте недостаточно

Скрытая кнопка не мешает отправить `POST /api/favorites/...` напрямую. Route Handler всё равно вызывает `getCurrentUser`. Проходящие тесты подтверждают сформулированный сценарий, а не полную безопасность системы.
